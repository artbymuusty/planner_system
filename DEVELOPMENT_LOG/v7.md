## 🆕 Aşama 2 — `useProactiveAssistant` Hook'u

`src/hooks/useProactiveAssistant.ts` (yeni dosya, ~400 satır).

### 2.1 Tasarım İlkeleri
> Asistan, kullanıcının veri akışını izleyip **kendiliğinden devreye girmeli** ama **aşırı konuşkan olmamalı**.

- **Frequency limit**:
  - `'daily'` modu → aynı trigger günde 1 kez
  - `'once'` modu → bir uniqueKey için ömür boyu 1 kez
- **Toplam günlük cap**: max 5 proaktif mesaj/gün (`DAILY_CAP`)
- **localStorage anahtarları**:
  - `proactive_<trigger>_<date>` veya `proactive_<trigger>_<uniqueKey>`
  - `proactive_count_<date>` (günlük sayaç)
- **Karma kaynak**: bazıları template (key gerekmez), bazıları AI (key yoksa sessizce atlanır)
- **Asla crash etmez**: tüm builder'lar try/catch ile sarılı

### 2.2 11 Trigger

| # | Trigger | Mod | Koşul | Kaynak |
|---|---|---|---|---|
| 1 | `postpone2` | once/event | postponeCount **2'ye** çıktı | AI varsa empati+öneri / fallback şablon |
| 2 | `postpone3` | once/event-count | postponeCount **3+** | AI alt görev bölme önerisi (3-4 madde) / fallback |
| 3 | `all_done` | daily | Bugünün tüm görevleri tamam (≥2 görev) | 5 motivasyon mesajından random pick |
| 4 | `overdue` | daily | 3+ geçmiş tarihli açık görev (postpone'lanmamış) | Şablon — örnek isimler dahil |

### 2.3 Postpone İzleme Mantığı
`prevPostponeRef` ile `Record<eventId, count>` saklanır:
- Her events değişiminde yeni snapshot alınır
- Önceki snapshot'la karşılaştırılır → her event için `oldCount → newCount` artışı tespit edilir
- `newCount === 2` → `postpone2` tetiklenir (uniqueKey: event.id)
- `newCount >= 3` → `postpone3` tetiklenir (uniqueKey: `${event.id}_${newCount}` → her artışta yeniden tetiklenebilir)
- İlk render'da `prevPostponeRef.current === null` → karşılaştırma atlanır, sadece snapshot kaydedilir (mount'ta gereksiz tetikleme yok)

### 2.4 AI Promptları (Türkçe, sade düz metin)
İki AI trigger için detaylı promptlar yazıldı; tümü:
- **Markdown KULLANMA** notu içerir
- 2-3 cümle / 3-4 madde sınırı verir
- Kategori, önem, postponeCount gibi context'i verir

Örnek (`postpone3`):
> Kullanıcı "<görev>" görevini N. kez erteledi. Bu görev muhtemelen büyük geliyor. Türkçe yanıt ver: önce 1 cümle empati. Sonra "Bunu şu küçük adımlara bölelim:" diyerek 3-4 küçük somut alt parçaya böl, her birini "• " ile başlatarak madde madde liste yap. Markdown başlık/kalın KULLANMA, sade düz metin yaz.

### 2.5 PlannerApp Entegrasyonu
[src/components/PlannerApp.tsx](src/components/PlannerApp.tsx):
```ts
const [proactiveMsgs, setProactiveMsgs] = useState<ProactiveMessage[]>([]);

useProactiveAssistant(
  planner.state.events,
  modules.modState,
  useCallback((msg: ProactiveMessage) => {
    setProactiveMsgs(prev => [...prev, msg]);

// JSX:

  onOpenSettings={() => setActiveModule('settings')}

```

Tek yönlü akış: hook → state → AssistantWidget. Widget kendi içinde `consumedProIdsRef` tutarak duplicate'i engeller.

## 🆕 Aşama 3 — Özelleştirilebilir Kategoriler

[src/components/calendar/CalSidebar.tsx](src/components/calendar/CalSidebar.tsx) **+331 / -29** satır.

### 3.1 İhtiyaç
v6'daki kategoriler 5 sabit (`personal/work/study/health/other`) ve **isimleri değiştirilemiyordu**. Kullanıcı kendi etiketlerini istiyordu (örn. "Diğer" → "Hobi", veya tamamen yeni "Aile" kategorisi).

### 3.2 İki Kanallı Sistem

**A. Built-in kategoriler (5 adet, type-safe)**
- `EventCategory` enum'u dokunulmadı (events veri tabanı bütünlüğü için)
- Görüntü tarafında **override** edilebilir:
  - `BUILTIN_LABELS_KEY = 'hackplanner_builtin_cat_labels'` → `Record<EventCategory, string>` (yeniden adlandırma)
  - `DELETED_BUILTINS_KEY = 'hackplanner_deleted_builtin_cats'` → `EventCategory[]` (sidebar listesinden gizler, event verisi korunur)

**B. Custom kategoriler**
- `CUSTOM_CATS_KEY = 'hackplanner_custom_cats'` → `{ id, name, color }[]`
- `HIDDEN_CUSTOM_CATS_KEY = 'hackplanner_hidden_custom_cats'` → `string[]` (gizleme)
- `CUSTOM_CAT_PALETTE`: 7 renkli pastel paleti (mor/pembe/turkuaz/yeşil/turuncu/eflatun/açık-mavi)

### 3.3 Unified Render
Her iki kategori türü tek listede render edilir:
```ts
[
  ...BUILTIN_CATS
    .filter(b => !deletedBuiltins.includes(b.key))
    .map(b => ({
      id: 'builtin:' + b.key,
      isBuiltin: true,
      builtinKey: b.key,
      label: builtinLabels[b.key] || b.defaultLabel,
      color: b.color,
      isHidden: hiddenCategories.includes(b.key),
    })),
  ...customCats.map(c => ({
    id: c.id,
    isBuiltin: false,
    label: c.name,
    color: c.color,
    isHidden: hiddenCustomIds.includes(c.id),
  })),
]
```
Hepsi aynı satır şablonunu kullanır → kod tekrarı yok, davranış (toggle/rename/delete) tek yerden yönetilir.

### 3.4 3-Nokta Menü
Her kategori satırında `MoreVertical` (lucide) ikonlu buton:
- **Hover'da** veya **menü açıkken** görünür (`opacity` transition)
- Açılınca popup: `Pencil → Yeniden adlandır`, `Trash2 → Sil`
- **Outside click** ile kapanır (`mousedown` listener, `setTimeout(0)` ile mevcut event'in kapatmaması için)
- `aria-haspopup="menu"`, `aria-expanded`, `role="menuitem"` accessibility

### 3.5 Yeniden Adlandırma Akışı
- Menüden "Yeniden adlandır" → `editingId` set edilir, `editingName` mevcut adla doldurulur
- Satır içindeki span yerine input render edilir (`autoFocus`)
- `Enter` → commit, `Escape` → cancel, `onBlur` → commit
- Built-in'lerde `builtinLabels` map'ine yazılır, custom'larda dizi item güncellenir

### 3.6 Yeni Kategori Ekleme Formu
- Kategori başlığı yanına `+` butonu (toggle: `+` ↔ `X`)
- Açılan form: input + renk paleti (7 dot)

### 4.2 Pomodoro Tam Ekran
[src/components/modules/StudyOverlay.tsx](src/components/modules/StudyOverlay.tsx):

Yeni state: `pomodoroFullscreen: boolean`. Aktif çalışma kartının başlığına `Maximize2` butonu eklendi.

**Layout etkisi**:
- Bookshelf alanı `display: none` olur
- `module-grid` `1fr 380px` → `1fr` olur (sidebar gizlenir)
- Sağdaki "Performance Stats / Music / vb." sidebar `display: none` olur
- Çalışma masası tek başına ekranı kaplar

**Otomatik bağlama**:
```ts
const next = !pomodoroFullscreen;
setPomodoroFullscreen(next);
if (next && !focusMode) onToggleFocus();   // tam ekran açılırken odak modu da açılır
if (!next && focusMode) onToggleFocus();   // tam ekran kapanırken odak modu da kapanır
```

Ayrıca odak modu butonu manuel kapatılırsa, tam ekran açıksa o da kapatılır:
```ts
onClick={() => {
  if (focusMode && pomodoroFullscreen) setPomodoroFullscreen(false);
  onToggleFocus();
}}
```

Mantık: **Tam ekran ⊃ Odak modu**. Tam ekran açıkken odak modu zaten açık olmak zorunda.

### 4.3 Focus Mode CSS Revizyonu
v6'da focus-mode "sidebar'daki diğer butonları gizlerken focus butonunu açık bırakan" karmaşık bir kuraldı. Buton sidebar'dan gittiği için:

```css
/* SİLİNDİ */
.focus-mode .sidebar button:not(#focusBtn) { display:none; }
.focus-mode .sidebar .sidebar-sep { display:none; }
.focus-mode .focus-toggle { ... }

/* EKLENDİ */
.focus-mode .sidebar { display: none; }
.focus-mode .main-area,
.focus-mode .main-content { /* tam genişlik */ }
.focus-mode .module-overlay { /* z-index, edge-to-edge */ }
.focus-mode .module-overlay .module-header { /* sticky/clean */ }
```

Yani odak modunda artık **sidebar tamamen kaldırılır**, calendar zaten v6'da gizleniyordu, study overlay tüm ekranı kaplar.

## 🛠️ Teknik Notlar

- **TypeScript build**: Tüm aşamalar sonrası TS hatası yok
- **Hook hijyeni**: `useProactiveAssistant` 11 ayrı `useEffect` içeriyor — bilinçli tercih. Her trigger'ın bağımlılık dizisi farklı (örn. `[modState.water, emit]` vs `[modState.gym, emit]`) → tek useEffect'te birleştirmek **yanlış re-trigger** üretirdi
- **`emit` referans stabilitesi**: `useCallback` ile `[onMessage]` bağımlılığı → onMessage de PlannerApp'te `useCallback`'le sarılı → stabil → useEffect'ler her render'da boşa tetiklenmez
- **localStorage rate limit**: Daily cap'in **takvim günü** bazında olmasının nedeni — kullanıcı uygulamayı saat 23:55'te açıp 5 mesaj alsa bile, 00:00'da yeni güne yeni quota başlar. Saat dilimi `formatDate(new Date())` ile lokal
- **`shouldFire` boundary**: Cap dolduğunda **mode'a bakılmaz** → `'once'` mesajı bile cap dolu günde atılmaz. Doğru mu? Evet — kullanıcıyı bombardıman etmemek için
- **Proaktif promise leak yok**: `emit` async builder'ı bekler ama `try/catch` ile sarılı, ayrıca state setter'ı `setProactiveMsgs` setter callback'iyle çalışır, stale closure riski yok
- **Custom kategori → event filtreleme**: Henüz event'lere custom category atanamıyor (EventCategory enum sabit). Bu **bilinçli sınır** — v8'de event'e `customCategoryId?: string` opsiyonel alan eklenebilir. Şu an custom kategoriler "hatırlatma etiketleri" gibi davranıyor
- **AssistantWidget overflow**: Panel `position: fixed`, `bottom: 24px`, `right: 24px`. Mobile'da `max-width: calc(100vw - 32px)` ile sığar
